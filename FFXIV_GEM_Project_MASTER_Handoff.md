## WHAT THIS PROJECT IS
An FFXIV x D&D 5e homebrew run by THREE Gemini Gems (Campaign / Loremonger / One-Shot) sharing ONE knowledge set (00-08). The GM is human; the Gem is the behind-the-scenes DM assistant. English instructions, Italian output. Campaign arc = A Realm Reborn -> Endwalker (Dawntrail excluded from the CAMPAIGN only; Loremonger/One-Shot are unlimited).

## ARCHITECTURE (2 layers)
- **CONTROL layer** = the 3 Gem instruction .txt, built from GEM_master.json via the SSOT Builder (GEM_Builder.html). RULE ZERO + IRON RULES are restated in each box ON PURPOSE (redundancy is load-bearing). MODEL POLICY: Campaign + One-Shot run on PRO (play); Loremonger runs on FLASH (light utility: backgrounds, on-the-fly shops/monsters, NEVER a beat), so tplL keeps a fuller form. COMMAND MODEL (v220): Campaign + One-Shot are SINGLE COMMAND EXECUTORS - every action is a SLASH COMMAND ('/continua','/stop','/load','/nota','/esito',...); a message with NO '/' takes NO game action (brief plain answer, no meta/mode preamble). LOAD = '/load' (a complete '=== SAVE ===' block pasted alone also loads). System notes = '/nota' / '/esito' (slash, no colon; 1-line ACK, never conversational). Loremonger stays conversational. LANGUAGE CONVENTION (binding): instructions AND knowledge are ENGLISH; only OUTPUT and COMMAND WORDS are Italian - literal Italian output strings ('Ancora save:', 'Da leggere ai PG', markers, one-line GM redirects) stay Italian because they ARE output; all instructional prose and examples are English.
- **DATA layer** = knowledge 00-08, RAG chunk-retrieved (only a fraction is in context at a time).
- **INDEPENDENT VERSIONING**: each file bumps on its own; version in its own header. Knowledge = MAJOR.MINOR (06 v4.x / 07 v1.x / 08 v3.x); control layer (master + 3 .txt) = integer vNNN.
- **DUAL-DELIVERABLE**: a change touching BOTH layers ships master + the patched knowledge file; a knowledge-only change ships just the file(s). Every export is ZIPPED (BP #14).

## *** THE CORE LESSON - why commands slipped, and the cure (RESOLVED 2026-07-16) ***
The long saga where an end-of-session command ('fine sessione' / 'salva' / 'stop') PLAYED A BEAT instead of the save gate (v189-v208) was NOT a rule bug and NOT the command word. Two red herrings were chased for many bumps:
1. the PER-BEAT ANCHOR reprinting save vocabulary every beat (v199-v202);
2. the command LEXEME itself (v203-v208: neutral markers -> retire 'fine sessione' -> rename 'salva'->'stop' -> strict single word + guard).
Both failed IDENTICALLY: even the unambiguous HALT word 'stop', right after one beat, was run as the next beat.
**ROOT CAUSE = TOTAL always-on context load over a threshold.** Under load the model collapses EVERY post-beat command to the momentum default ('play the next beat'); 'continua' only looks reliable because it equals that default. Proven by the 'nudo Gem' test (instructions-only routes clean; the full knowledge set breaks it, identically on v169 and v202).
**CURE = DIET, not teeth - and the dominant lever is the CONTROL .txt weight (it is 100% in context every turn, unlike RAG knowledge).** v209 reverted the disproven command-word teeth to terse + moved heavy detail (economy/loot/session-0) to 06 pointers -> the built Campaign .txt went **49.5k (v208) -> 42.1k (v209), back to the ~41.7k v169 'known-good' baseline**. **Pro test PASSED: load -> continua -> stop -> confermo, and 'stop' produced the READ-ONLY recap + gate, NO slip.** The data-file diet (05/07/08) trimmed the RAG side too. Lesson banked as BP #15/#16: MEASURE and REDUCE total load BEFORE adding teeth; keep the always-on .txt lean.

## *** UPDATE (2026-07-17) - THE AMBIGUITY LEVER + THE SLASH-COMMAND EXECUTOR ***
The weight/diet cure (CORE LESSON) is necessary but the deeper mechanism is AMBIGUITY, not raw byte-count: the GM confirmed the 'golden run' had LARGER instructions yet routed clean because it was COHERENT. The v210-v217 cycle added competing dispatch teeth; under load the model resolved the ambiguity by falling to the continue-momentum default (the one-turn lag). Findings: three different command words all failed IDENTICALLY -> the lexeme/teeth are not the lever; EXTENDED REASONING made NO observable difference on Pro -> not reasoning depth either (behaviour-neutral; the GM keeps it ON because it consumes fewer tokens for them).
THE FIX (v218-v220): a SLASH-COMMAND EXECUTOR - every action is a '/command' (a single explicit control glyph removes the command-vs-narration ambiguity at the ROOT and let us DELETE dispatch teeth). v218 introduced the '/' channel; v219 put all instruction examples in English; v220 SIMPLIFIED to a SINGLE executor: dropped the 'free chat mode' framing + its verbose disclaimer (a no-'/' message just gets a brief plain answer, NO meta), made LOAD an explicit '/load' (fixes the observed load difficulty), and turned save notes into '/nota' / '/esito' (slash, no colon; system notes, 1-line ACK, never conversational). [Info GM] is ONE line (no 'Nota:'/'Pin roster:' addendum).
BANNED: any 'mode'/status/meta preamble ('sistema inizializzato','database caricati','modalita chat') - A1 NO-META. LANGUAGE: instructions + knowledge ENGLISH; only output + command words Italian.
STATUS: v219 Pro test - /tracker entered first try (correct); /stop needed one regenerate; the verbose chat-mode disclaimer + a load hiccup drove the v220 simplification. Pending: heavy Pro test on v220.

## *** UPDATE (2026-07-19) - RADICAL MINIMAL ROUTER BOX + THE REAL COMMAND-SLIP ROOT CAUSES ***
The command-slip persisted past the diet. Root cause was NOT total load alone. Two concrete PROMPT-STRUCTURE bugs were isolated by A/B vs the v169 known-good file and fixed:
- AUTO-LOAD-ON-BARE-BLOCK (v228 / 06 v4.32): 06 said a pasted '=== SAVE ===' block auto-loads WITHOUT a command. The block never leaves context, so every later turn RE-FIRED /load ('does only /load'). FIX: LOAD IS COMMAND-ONLY - a load happens ONLY on the explicit '/load'; a resident block is INERT. (V169 had no auto-load and needed no LOAD-ONCE guard.)
- ECHO SELF-COPY (v229): the '▶ ESEGUO <cmd>' control line (added v223) was itself COPIED from the model's OWN previous turn - given /continua it reproduced the previous '▶ ESEGUO /load'. FIX: the echo line was REMOVED entirely; the box executes the newest '/command' directly.
ALSO: the Campaign box was rewritten as a RADICAL MINIMAL ROUTER (~2.5k, was ~40k) per Google's Gemini-3 + Gems guidance (reliable instruction-following degrades past ~1.5k; critical rules LAST; persona-light; EXACT-FILENAME knowledge anchoring; {curly} placeholders, not <angle>). Structure: ROLE -> KNOWLEDGE-AUTHORITATIVE (by exact filename) -> OUTPUT RULES -> COMMANDS (one-liners -> 06 sections) -> EXECUTION CONTRACT (last, wins). ALL behaviour detail stays in 06 (RAG). tplL/tplO keep the older fuller form (execHeader/rz/iron) - not part of the failing test, left as-is until re-tested.
TEST v229 (Pro) PASSED routing: /load -> /continua (dungeon) -> /tracker -> /stop (gate) -> /confermo (write), no slip, no re-load.
06 v4.33 content fixes (knowledge, program-style): (1) INTERLUDE READ-ALOUD - every interlude/enigma opens with a 'Da leggere ai PG' narration BEFORE the 'Soluzione:' line (§B12/§B20). (2) DUNGEON-COMPLETION FIDELITY - write 'completato <duty>' only when the FINAL boss is defeated; a mid-dungeon /stop writes the actual partial position and resumes mid-dungeon (§B17). (3) DUNGEON OST CADENCE - battle theme at EVERY statted encounter + ambient RESTORED at each interlude between fights (§A23).
NOTE: the old DIET/AMBIGUITY lesson stays valid (weight matters) but is SUPERSEDED as the PRIMARY fix - the decisive levers were the two prompt-structure bugs above, found by the V169 A/B, not raw byte-count.

## EDITING BEST PRACTICE
> **COLD-START DIRECTIVE (read first):** EVERY change goes through these BPs - no ad-hoc edits. Tie each edit to an OBSERVED Pro-baseline failure; CLASSIFY it (compliance slip -> salience at >=2 obs; mechanism/capability gap -> root-cause fix at the 1st); apply it as a SCRIPTED, ASSERTED, RAG-aware, surgical edit rebuilt from the LAST user-provided file; RECONCILE, do not accumulate; log it; consolidate every ~8-10 bumps; ALWAYS deliver zipped. Before patching a ROUTING failure, MEASURE total load and DIET first (the v189-v208 saga proves teeth do not fix a load problem).

1. **GENERAL PRINCIPLE + TEETH + ONE EXAMPLE** - never a closed enumeration (a list reads as exhaustive -> anything unlisted becomes inventable).
2. **POSITIVE FRAMING** (do X) over walls of prohibitions.
3. **SURGICAL, ANCHORED EDITS** - a rule lives in ONE home + at most a terse ECHO elsewhere.
4. **TWO FAILURE KINDS:** COMPLIANCE SLIP (rule exists, model slipped) -> salience ONLY at >=2 Pro observations (a single slip is variance). CAPABILITY/MECHANISM GAP (model COULD NOT comply: data out of context, unusable command surface, two rules in tension) -> root-cause fix at the FIRST observation.
5. **MECHANISM OVER EXHORTATION**: if a failure is data-availability, re-emit the datum NEAR the point of use (the LOAD ANCHOR ECHO pattern).
6. **RECONCILE, DO NOT ACCUMULATE**: when a behaviour slips, find the rule/format pulling the other way and fix THAT; A/B against the last-known-good file to isolate the ONE correlating variable (this is how the diet lever was found).
7. **TEETH PLACEMENT (weight-aware)**: beat-scoped FORMAT rules land fine from 06 (RAG) alone; keep tplC teeth ONLY for cross-cutting always-on behaviours (save, flow pointers, markers, dispatch). Escalate a 06 rule into tplC only if it keeps failing after a mechanism fix - AND mind the ceiling (BP #16): heavy detail belongs in 06, reached by a one-line pointer.
8. **RAG-AWARE FORMATTING**: chunkers split on blank lines/headers -> co-dependent rules + their exceptions stay on ADJACENT lines in one cluster; cut decoration, never the structure.
9. **SCRIPTED, ASSERTED EDITS**: deterministic script, unique-anchor asserts, verbatim check for form-only refactors; chains rebuildable from the last provided file -> rollback + bisection are binary. For a DATA-file dedup, verify with a fact-extractor diff (0 facts lost).
10. **SALIENCE BUDGET & CONSOLIDATION**: salience inserts inflate the file; observed-Nx notes are CHANGELOG, not rule. Every ~8-10 bumps run a consolidation (form-only, verified) that folds landed salience into home rules and strips metadata. If everything is salient, nothing is.
11. **MODEL-TIER BASELINE = PRO**: Flash observations do NOT count toward the >=2 threshold unless reproduced on Pro (Flash slips for its own reasons - a Flash FAIL is a false negative, a Flash pass is weak evidence).
12. **TEST PROTOCOL**: short sessions (2-4 beats; a dungeon counts double) with a save checkpoint before big setpieces. BUT the DECISIVE test for the load-slip is a LONGER/heavier Pro run (that is where the ceiling bites). Tail-test the save cheaply: load -> 1 beat -> stop -> confermo.
13. **AUDIT ALL REFERENCES ON A STRUCTURAL CHANGE**: when a shared datum changes shape, grep EVERY consumer and confirm each still has a valid source.
14. **DELIVERY IS ALWAYS ZIPPED**: bundle, standalone refreshed file, or fixture - always a .zip, never a loose file (the GM cannot see loose exports).
15. **TOTAL CONTEXT BUDGET IS A FAILURE VECTOR (RESOLVED via the diet)**: past a threshold the model stops reliably obeying commands regardless of how correct the rules are. Cure = diet (see THE CORE LESSON). Every rule/word added has a context COST.
16. **INSTRUCTION-WEIGHT CEILING (the always-on layer is the high-leverage lever)**: the built Campaign .txt has a WORKING BUDGET ~42-45k chars; past ~49k the command-slip returns. tplC chars cost FULL always-on weight; RAG knowledge (00-08) does NOT. So: prefer a one-line tplC pointer + the full rule in 06; MEASURE the built .txt after any control-layer change; run a consolidation when tplC creeps toward ~49k. (v208 49.5k slipped; v209 42.1k did not.)
IN SHORT: compliance slip -> salience at >=2 Pro obs; mechanism gap -> root-cause at 1; every edit scripted+asserted, RAG-aware, reference-audited, logged, zipped; DIET before teeth; keep the always-on .txt lean.

## MSQ FLOW ENGINE (08.1 / 06 Part B / master)
- **PILLARS != BEATS**: Roadmap bullets are milestone guardrails, NOT the beat list. The real beats = the wiki quest chain walked IN ORDER, on-site, canonical NPCs. One continua = ONE chain step (never pillar-to-pillar; no hub-exposition dump; never relocate on-field info onto a hub NPC).
- **SUB-BEAT GRANULARITY + CONDENSE-FIRST**: one continua/prepara = ONE digestible sub-beat (~one wiki step, ~5-8 min); BEFORE splitting, check the FETCH AUTO-CONDENSE. SCOPE != DEPTH: narrow the scope, never thin the canonical dialogue. Dungeon/Trial carve-out: delivered in the FEWEST COMPLETE chunks, never fight-by-fight.
- **FETCH AUTO-CONDENSE**: a RUN of 2+ consecutive pure-fetch quests -> ONE lore-preserving vivid bridge that STOPS at the first SUBSTANTIVE beat (played in full); a substantive quest is NEVER condensed; the condense is never announced. NAME-FREE controls: 'riassumi [fino al prossimo ...]' / 'gioca' (the GM need not remember quest names).
- **CONTINUITY HANDOFF (STRICT)**: re-read the previous close + [Info GM]; carry forward VERBATIM every named element of ANY kind (place/NPC/ally/ENEMY-or-BOSS/info-source/promise/turn-in/reward/next-step); the beat's FIRST in-fiction line re-states what it inherits. Handoff binds CONTENT; the wiki spine binds ORDER (spine WINS over a wrong previous [Info GM]; a skipped step folds/drops, never resurrects).
- **STAGING IS FLOW**: where a scene happens, who is present, the in-quest order follow the wiki step spine - FIXED; only prose/color/loot/dice/vendor-special vary.
- **[Info GM] = ONE line**: 'chiude <A>; apre <B>' ONLY on a true A->B transition, else 'prosegue <quest>; prossimo step wiki: <next>'. ATOMIC STEP (one discrete objective, never 'X per poi Y'); SPINE-SOURCED (read from the cached 08 index, never memory-invented); NOTHING forward (no gated reveal name/event, no future roster, no parked hook).
- **BOUNDARY MARKER = COMMAND-NEUTRAL**: '- fine beat . comandi: continua . prepara . stop -' with NO beat/quest name and NO teaser (the name is stated once, in [Info GM]). The LOAD recap uses its own distinct '- caricamento completato . comandi disponibili: continua . prepara -'.
- **DIALOGUE = PLAYED SCRIPT (both modes)**: near-fully-voiced canon-anchored exchange; attitude/knowledge shown THROUGH the lines; the 'Atteggiamento:'/'Cosa sa:' sidebar labels are BANNED in output. PRE-DUNGEON BRIEFING = its OWN beat.
- **TRAVEL - VIAGGIO NON-TRIVIAL-ONLY**: the (compass) travel line + 'viaggio' offer appear ONLY for a non-trivial journey (teleport blocked / long or cross-region / first-time); a trivial teleport hop gets none - 'continua' arrives compressed. A played [VIAGGIO] beat is TRANSIENT (cursor NOT advanced, not saved) + arrival-only marker -> next continua plays the destination. FOOTER order = [Info GM] -> (compass, if non-trivial, at END) -> Rif. scontri line -> marker.
