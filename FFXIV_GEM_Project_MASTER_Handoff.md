# FFXIV x D&D 5e - CAMPAIGN PROJECT MASTER HANDOFF (evergreen)

> Version-agnostic ON PURPOSE. This doc describes the ARCHITECTURE + BEHAVIOUR, never version numbers. Each file's current version lives in its OWN header. Check there, not here.

## WHAT THIS PROJECT IS
An FFXIV x D&D 5e homebrew campaign assistant. The GM is human; the assistant works behind the scenes and never speaks to the players. English instructions, Italian output. Campaign arc = A Realm Reborn -> Endwalker (Dawntrail excluded from the CAMPAIGN only).

**PLATFORM (current, since 2026-07-21): a CLAUDE PROJECT.** The Campaign moved off Gemini after its command layer proved unfixable across ~10 attempts (see the CORE LESSON below). The Gemini Gem is retained as a BACKUP and as a PROSE ORACLE — its Italian is still the register benchmark, and good passages from its runs are harvested as style exemplars for 06 §A1. Loremonger and One-Shot still run as Gemini Gems on the same knowledge set; improvements made for the Campaign are inherited by them later. Everything below describes the Claude Project unless it explicitly says otherwise.

## ARCHITECTURE (2 layers)
- **CONTROL layer** = the Project's custom-instructions box (`GEM_Campaign_Instructions_CLAUDE.txt`, versioned cvNN). 100% in context on EVERY turn — this is the ONLY guaranteed-present surface, so anything needed on EVERY beat (command contract, prose register, high-frequency name bindings) lives HERE. Everything looked up only when relevant stays in the knowledge files.
- **DATA layer** = knowledge 00-08, **RAG chunk-retrieved** — only a fraction is in context at a time. CONFIRMED 2026-07-21 from the Project UI ("Modalità di ricerca" active at 20% capacity): Claude Projects runs retrieval here, not full context, and there is NO toggle to force full context. So RAG-friendly structure (headers, bullets, blank-line boundaries, one rule per line) remains REQUIRED, and a rule that must fire every turn cannot live only in a knowledge file.
- **COMMAND MODEL**: a SINGLE COMMAND EXECUTOR — one slash command per turn, run exactly it, then stop. ONE NAME PER ACTION, NO ALIASES. The '/' is a CHANNEL SEPARATOR, not decoration: it distinguishes an out-of-fiction instruction from narration ("il gruppo continua verso il fondo" vs '/continua'), an ambiguity that exists regardless of model capability. Commands: '/continua', '/prepara', '/fine sessione', '/salva', '/viaggio', '/tracker', '/voci', '/recap', '/mappa MSQ', '/riassumi', '/gioca', '/subquest', '/torniamo alla MSQ', '/nota', '/esito', '/sessione 0', '/cambio Classe'. END OF SESSION IS TWO COMMANDS and the split IS the safety mechanism: '/fine sessione' (read-only recap + gate) then '/salva' (writes). LOAD HAS NO COMMAND — a '=== SAVE ===' block in the GM's CURRENT message is itself the trigger, since that marker cannot occur in narration.
- **LANGUAGE CONVENTION (binding)**: instructions AND knowledge are ENGLISH; only OUTPUT and COMMAND WORDS are Italian - literal Italian output strings ('Ancora save:', 'Da leggere ai PG', markers, one-line GM redirects) stay Italian because they ARE output; all instructional prose and examples are English. Do NOT translate the corpus to improve the Italian: most of it is DATA (stat blocks, indexes, tables) whose language does not affect narration, and the canonical FFXIV names must stay English or the §A14 wiki verification breaks. The lever for prose is EXEMPLARS, not language (see the register section of 06 §A1).
- **INDEPENDENT VERSIONING**: each file bumps on its own; version in its own header. Knowledge = MAJOR.MINOR (06 v4.x / 07 v1.x / 08 v3.x); control layer = cvNN.
- **DELIVERY**: a knowledge change ships the changed .md file(s) to re-upload; a control change is pasted into the Project's instructions box. VERIFY THE DEPLOYED VERSION BEFORE TRUSTING A TEST — a whole test cycle was once misread because the Project was still running cv2 while the working copy was at cv7.

## *** THE CORE LESSON - why commands slipped, and how it actually ended (RESOLVED 2026-07-21 by leaving the platform) ***
For ~40 versions an end-of-session command PLAYED A BEAT instead of the save gate. FOUR successive theories were chased, and the first three were all WRONG — recorded here so none of them is chased again:
1. **The PER-BEAT ANCHOR** reprinting save vocabulary every beat (v199-v202). Failed.
2. **The command LEXEME** (v203-v208: neutral markers -> retire 'fine sessione' -> rename 'salva'->'stop' -> strict single word + guard). Failed identically: even the unambiguous HALT word 'stop', right after one beat, ran as the next beat.
3. **THE DIET THESIS — total always-on context load over a threshold** (v209, banked at the time as BP #15/#16). **FALSIFIED and RETIRED.** The measurement that killed it: the known-good v169 build is **42,050 B** and the broken v212 is **41,885 B** — the working version is BIGGER. Size was never the variable. Do NOT resurrect "cut bytes until commands work".
4. **THE ACTUAL ANSWER: the platform.** The final Gemini test (v238, the most instrumented instruction layer the project ever had) failed three commands out of five, and '/stop' emitted **raw tool-call JSON of search queries** — internal scaffolding leaking into output, twice, byte-identical. That is not prose gone wrong; it means the instruction layer is not being read at that point at all. **No prompt can reach that level.** The same commands, on the same knowledge, worked FIRST TRY and repeatedly as a Claude Project.
**THE GENERALISABLE LESSON:** distinguish a problem you own from a property of a closed product you do not control. Prose quality is tractable (exemplars measurably moved it in one iteration); a host that bypasses its own instruction layer is not. Ten fix attempts against an intractable problem is the real cost recorded here.
**WHAT DID HELP, AND STILL DOES:** (a) SEMANTIC ACCURACY IN COMMAND NAMES — '/stop' was the worst offender ("stop WHAT?") and its genericness plausibly fed its own unreliability; every command now names exactly what it does. (b) THE READ/WRITE SPLIT — '/fine sessione' cannot write because '/salva' has not been typed yet, so the invariant is enforced by vocabulary instead of by teeth. (c) RECONCILING CONTRADICTIONS — §B17 and §B24 each simultaneously banned a trigger and gave a full procedure for it; a model retrieving either found "reject X" and "on X, do the full thing" at once. Prefer these three over adding emphasis.
